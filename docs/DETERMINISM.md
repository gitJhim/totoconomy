# Determinism and continuations

Guarantee: same supported executable/environment, model, normalized scenario, seed, and intervention schedule produce equal canonical economic state and ordered economic facts. Arbitrary architectures, compilers, future models, and floating-point performance fields are outside this established boundary. Authoritative execution is single-threaded.

Normalization sorts firms/households by lexicographic ID and products by name; product maps are ordered. Arrays of knowledge and orders have deterministic insertion/update order. Household scarcity allocation rotates daily. Sorting is explicit; no pointer addresses, hash-table ordering, thread scheduling or wall-clock values influence behavior.

There is no mutable RNG cursor. Directory-notice selection uses a SplitMix64 mixing function keyed by `(seed, day, normalized household index, purpose=1)`, with exact unsigned 64-bit wraparound and modulo retailer-count mapping; the implementation constants and mapping are in `model.cpp`. This small modulo bias is part of the defined rule. Initial endowments are scenario data, tie-breaking is deterministic, and Stage 1 has no stochastic outside shocks. Future initialization/shock/search streams must use separate purpose keys and stable process identities. Branch names, log levels and output paths are not keys. A public-board branch can skip directory choices without changing another process's random schedule.

`--until-day D` executes until the boundary after days `[0,D)`. A checkpoint with `next_day=30` restores before arrivals/work/shopping on day 30. Older targets are rejected; a resume to the same boundary is an empty continuation, while branches require a later target. Checkpoint state contains every current future-relevant field: cash/stock/reservations, outstanding arrivals with fixed invoice, employment/configuration, current prices, knowledge, board mode, seed, day, next event/order/decision IDs. Inventory aging and random cursors are absent because the model does not use them.

Canonical state digest = FNV-1a-64 over compact, sorted-object-key UTF-8 JSON from `State` (`nlohmann::json::dump()`, no whitespace, integer tokens). Arrays preserve normalized/creation order. Hex is 16 lowercase digits. Checkpoint integrity separately hashes its complete envelope without `checkpoint_digest`. Neither uses `std::hash`. State digests exclude run path/labels, parent metadata, scenario display name, build identity and all measurements. The schema/model and normalized scenario are stored alongside state, with a separate scenario digest/origin. FNV is a reproducibility checksum, not a security signature.

A no-op branch applies no state mutation, consumes no random choices and allocates no economic record IDs. Its continuation events and final state equal the baseline suffix. A public-board branch sets only information mode at its boundary, records one intervention event, and publishes the board during that day's information phase. The pre-intervention `initial_state.json` is identical to the checkpoint. Earlier records remain in the immutable parent. Changed information may change later resources and event counts.

- **Resume** executes new days from complete stored state into a new run directory.
- **Re-simulation** executes recorded configuration/seed again and compares facts/state; the acceptance suite performs this with repeated `run` calls. There is no separate replay-execution command.
- **Presentation replay** reads exported display records; no policy is re-executed. The foundation supplies the contract, not a player.
- **Branch** restores state, applies one validated no-op or board intervention, then executes a new shared interval.

Comparison requires completed verified runs with matching model, normalized origin, scenario and seed, allowed intervention types, and an explicitly shared `[from_day,until_day)` interval. Different-start continuations must match the earlier run's checkpoint envelope at the later start boundary; retain that checkpoint for comparison. Same-start runs must have identical pre-intervention state. This conservative rule rejects unrelated or unprovable pairings; it is not a general ancestry graph or batch experiment system.
